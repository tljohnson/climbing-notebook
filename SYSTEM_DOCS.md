## Architecture Overview

Climbing Notebook is an offline-first personal climbing notebook, iPhone-primary with minimal iPad support, targeting iOS 17.5+ with SwiftUI. See [README](README.md#climbing-notebook) for primary and minimum-support runtime targets; preserve actual device/runtime labels in evidence. The approved architecture routes presentation through feature coordinators to app-private SwiftData persistence and managed-file services. The main app alone owns library mutations and managed originals. Future share delivery must use an App Group mailbox for main-app intake and draft review; portable backup must use explicit data-transfer models plus originals, not a raw database copy. These are approved architectural contracts, not claims that intake or backup exists. See [architecture](ClimbingNotebook-Offline-iOS-Notebook-Architecture-and-Implementation-FeaturePlan.md#5-architecture-and-technology-decisions).

The implemented [text notebook](ClimbingNotebook-Offline-iOS-Notebook-Architecture-and-Implementation-FeaturePlan.md#216-consolidated-text-notebook-milestone-approved) opens an initially empty `TextNotebook` format with hierarchy CRUD, notes, persisted sibling order and explicit Save/Cancel. The [image contract](Image-Supported-Notebooks-FeaturePlan.md) adds V1-preserving V2 storage and app-owned originals. Examples and unchanged-format retained content are separate sources; source-bound drafts prevent retargeting and retained reading cannot initialize an absent root. Retained fixture and diagnostic LibraryStore/generation roots are not the current notebook schema and remain isolated. Consult source, [current capabilities](README.md#current-capabilities) and [topic evidence](README.md#verification-references), not the plan's prospective file map. [Kanban](docs/WIP_KANBAN.md) owns status; implementation and passing checks do not establish owner acceptance, backup/recovery or safety as the only copy of valuable notes/images. Ordinary debugging needs no new approval; consequential runtime-floor/schema/architecture changes do.

## Cross-Cutting Invariants

- The main app alone mutates the library database. The extension must use the [mailbox contract](ClimbingNotebook-Offline-iOS-Notebook-Architecture-and-Implementation-FeaturePlan.md#72-share-extension-mailbox-contract), never direct library access.
- Never report saved/local success before originals and metadata are durably acknowledged. Preserve explicit save/recovery and file-ownership rules in the [data-integrity contract](ClimbingNotebook-Offline-iOS-Notebook-Architecture-and-Implementation-FeaturePlan.md#8-media-storage-and-data-integrity).
- Backup, generation recovery and URL-copy protections apply when implementing those dependent features, not as prerequisites for ordinary notebook work. Do not treat research harnesses as production readiness or restart paused investigations under an unrelated task.
- Explicit Save/Cancel is the approved editor contract, not a temporary exception awaiting autosave. Retain failed drafts/source identity; unacknowledged changes may be lost on termination. DESIGN owns composition; the current notebook and image contracts own operations/data boundaries.
- Historical fixture packets CF-07B/CF-07D were superseded by CF-07E; no separate acceptance or resumed qualification is requested. Preserve retained data/tests and research limitations; see the [archive disposition](docs/WIP_KANBAN_ARCHIVE_2026-11-05.md) only when history is relevant. Current notebook work does not resume deferred archive/migration investigations.
- No backend, account, OCR, synchronization, analytics, LLM calls or automatic route-field extraction is authorized by the current implementation scope. Use synthetic fixtures, not personal route libraries or copyrighted guidebooks; see [scope and guardrails](ClimbingNotebook-Offline-iOS-Notebook-Architecture-and-Implementation-FeaturePlan.md#212-permissions-and-guardrails).
- Use an English-first UI while preserving Unicode user content. Retain originals/raw text until explicit deletion; ready deliveries and saved drafts do not automatically expire. These owner-confirmed defaults are recorded in the [owner decisions](ClimbingNotebook-Offline-iOS-Notebook-Architecture-and-Implementation-FeaturePlan.md#21-confirmed-owner-decisions).
