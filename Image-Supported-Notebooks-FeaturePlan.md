## 1. Selected Journey and Scope

**Design reconciliation, 2026-11-09:** [DESIGN.md](DESIGN.md) owns the later owner-approved compositions, functional UI labels and current visual index. The images-first Route layout and original mockups below describe the initial image milestone, not a competing design target. Intended Route Details is written-sections-first with References later; applying it requires separately scoped work. Keep this plan's caption limits, source/UUID binding, batch/failure semantics, schema compatibility and original-file ownership intact. The approved pitch-reader Notes composition shows pitch notes; this plan's additional General-note presentation is not required by that newer composition. No new intake types or schema changes follow from visual approval.

**Recommend a contextual reading notebook, not a photo gallery:** ordinary route/pitch **Add Images → native Photos picker → review local copies/captions → Save → read original with complete notes → relaunch/read offline**. See [Stitch comparison and final proposed references](#6-proposed-image-notebook-exploration). Mockups are not native implementation, owner approval, provider testing or accessibility evidence.

- **Route:** compact Images / General / Pitches scroll-to-section actions; captioned **Route images** index first, then complete General notes and ordered pitches. Images lead because finding the right consolidated topo/approach/descent reference is the task; jumps prevent images burying notes/pitches. Optional captions and saved order, not mandatory categories, find the right image. No inferred descriptions, grades or extracted text.
- **Pitch:** retain pinned Previous/Next Pitch; complete notes lead, followed by **Pitch images** and a distinct **Route images (N)** link back to the route index. An Images jump near pitch context reaches images past long notes. Route images never merge into the pitch list. Show Notebook/area/route and pitch name/position where applicable; resolve owners by UUID, not position/name.
- **Zero/one/several:** no images retains today's notes/pitches plus one quiet Add Images action, no empty gallery/tutorial. One image gets approximately180pt-high aspect-fit preview/caption; several get approximately96pt-high aspect-fit previews, wrapping body captions, position and a whole-row Open Image action. Previews identify content, not replace reading. Never crop away screenshot edges or truncate authored notes. Uncaptioned fallback is Image N, not provider filename or a fabricated title. No second description field.
- **Manage Images** in the image-section menu opens a small owner-bound editor: saved sibling order, optional captions (maximum120 Swift characters, preserve exact UTF-8), Open Image, confirmed Remove Attachment. Native reorder plus Move Up/Down alternatives, disabled at ends. Confirmation marks removal in the draft; Save commits all changes, Cancel restores all. Parent route/pitch deletion names its attachment count and detaches links with the existing graph deletion. Never delete a Photos asset.
- A first useful engineering increment may deliver select/review/Save/read/relaunch before reorder/caption refinement, with stable selected order and the final safety model. Schema compatibility, explicit cancellation, file ownership and failures cannot be deferred to make that increment smaller. Full bounded acceptance includes management/removal.

**Reader:** native full-screen cover; Done returns to the same owner/scroll position. Identify owner, caption and Image N of M; siblings are only this owner. Start aspect-fit for orientation; offer Fit Width for dense/tall screenshots, Fit Image, pinch/double-tap zoom and two-axis pan. Support native-pixel inspection (at least1:1 for supported originals), without claiming enlargement restores absent detail. Controls stay outside the image viewport; all edges and the final line remain reachable. Dark mode must not invert original pixels. Explicit Previous/Next Image avoids swipe/pan conflict; zoomed horizontal gestures pan, not change image. New image starts at fit; retain per-image zoom/pan while this reader remains open. Notes opens a read-only, fully scrollable sheet: complete General for route images; complete pitch notes plus distinctly labeled General for pitch images. Closing Notes restores zoom/pan. Full caption wraps/scrolls in context if it cannot fit chrome. No editing/sharing/removal in reader. If another window removes the active link, return to owner with an unavailable message, never another image at that index.

**Exclude:** OCR/extraction, website capture, share-extension intake, camera capture, Files/PDF import, image crop/rotation/editing, Live Photo motion/video, deduplication/reuse/transfer, tagging/search dashboards, sync, export and backup/restore. Main plan §§6–8 and §11 remain prospective wider contracts; apply their immutable-original, attachment-ownership and transaction principles only as narrowed here.

## 2. Review and Save Boundaries

1. Add Images captures ordinary Notebook source token, route UUID, optional pitch UUID and route revision before system image-only Photos multi-selection, ordered selection and `.current` representation preference. No broad Photo Library/camera permission request. Picker Cancel changes nothing. Examples and retained reader hide add/manage, with source enforcement in operations as well as UI.
2. Picker completion opens a separate **Add Images** draft, not the text editor. General/pitch editors keep their independent Save/Cancel; no combined unsaved-note submission or second modal editor. Allocate stable operation/asset/attachment IDs per selection before async work. Immediately show loading rows; bounded/sequential copying/validation runs off main actor. Measurable progress or honest Loading image…, never fake percentages. Completion order does not determine order. Ready means independent validated local copy, not Saved.
3. Review gives uncropped previews, full-reader review, optional captions, Add More and Remove Selection. Partial failure keeps ready items and puts actionable failed rows first without changing recorded selection order. Save disabled while loading/unresolved failures remain. Retry failed item (reselect if provider access expired) or deliberately Remove Selection to save the reduced set. No silent partial success/automatic network retries. Add More appends; intentionally reselecting a photo creates a distinct attachment, not implicit deduplication.
4. Save disables duplicate submission/dismissal; revalidate source/owner/revision after awaits, publish originals, commit the batch in one metadata save. Only commit acknowledgment updates snapshot/status and dismisses. Wrong source/deleted owner/stale same-route revision retains buffer with Not saved and Cancel/confirmed reload, never retargets to displayed pitch. Reload explicitly discards this image draft before starting fresh. Unrelated-route edits need not invalidate it.
5. Publication or metadata-save failure retains images/captions/retry IDs and all prior saved content. Show actual category with Retry Save, Keep Editing or Discard Changes. Say free space only for space errors; cloud/provider may require connection; unsupported/corrupt requires remove/reselect. Never false Saved or generic storage-full diagnosis. Retry verifies same-ID published bytes/hash, never overwrites another file.
6. Cancel with selections/caption/order/removal/loading changes confirms Discard unsaved image changes? Keep Editing changes nothing. Discard cancels/drains work, invalidates late callbacks, releases providers and cleans only draft-owned unreferenced files. Dirty/saving interactive dismissal is blocked, matching current text editor. Leaving owner/source uses this boundary, not autosave. Clean editor closes directly.
7. Backgrounding does not save/discard; retain memory buffers while process lives, allow suspension/canceled loading with Retry on return. No background-execution guarantee. Termination loses unsaved buffers, matching text drafts; next open loads committed content and cleans abandoned operations ([§4](#4-original-files-and-ownership)). Commit-before-ack termination may reveal the committed batch after relaunch; never claim an unacknowledged Save definitely failed or automatically import again.

Reader loading is separate from provider loading. Failed thumbnail keeps caption/Open Image. Missing/unreadable original shows **Image unavailable on this device**, Retry and Return to Route/Pitch, preserves caption/position/metadata and other notes/images. Decode/unsupported errors identify inability to display; no cached-thumbnail substitution, auto Photos lookup or silent metadata removal. User can add a replacement and explicitly remove old attachment. Root/graph corruption still fails closed, but one missing file must not block the entire notebook's notes.

## 3. Architecture and Schema Compatibility

**Inspected baseline before implementation:** `TextNotebookView.swift` contained `TextRouteView`, `TextPitchView`, `TextNotebookEditor`; `TextNotebookState` kept plain saved snapshots separate from source/revision-bound memory drafts. `TextNotebookStore.execute` used fresh context/validation/revision checks, rollback, prepared snapshot and one explicit save without fallible post-save fetch. `TextNotebookSchemaV1` (1.0.0) had only Area/Route/Pitch/NoteSection/NotebookState; marker `TextNotebook-1:<mode>`, empty migration stages. No production media helper existed. Diagnostic `LibraryStore`/`LibraryGenerationManager` and cancel-only share extension remain separate, not attachment infrastructure. Current implementation/evidence belong in README and `docs/verification/NotebookPrototype.md`, not a claim that the baseline remains current.

**Proposed V2 (2.0.0):** freeze V1, add `TextNotebookSchemaV2` containing existing five model shapes plus **ImageAsset** and **ImageAttachment**. Asset: UUID, UUID-derived relative key, received filename (metadata only), actual UTType, byte count, SHA-256, pixel dimensions/orientation. Attachment: UUID, required route relationship, optional pitch belonging to that route, required asset, caption, contiguous zero-based order per `(routeID,pitchID-or-nil)`. Nil pitch means route-owned. Validate inverses, IDs unique across kinds, owner consistency, limits and exact sibling membership before save. Snapshots hold immutable ordered descriptors, not image buffers/SwiftData objects. No shared assets/persisted user drafts in slice; each selection gets its own asset/link, but cleanup must still check references.

**Explicit compatibility contract:** named V1→V2 migration upgrades existing ordinary Notebook and separately stored Examples in place, preserving every UUID including marker, exact authored UTF-8, grades/styles, graph, sibling order and notebook/route revisions. New attachment collections empty. Transition marker to `TextNotebook-2:<same mode>` within tested upgrade; source identity remains mode/root/marker UUID, never reseed. Fresh stores use V2. Retained `NotebookSchemaV1`/CF-07B and diagnostic roots untouched; no image seeds added to existing Examples. Demonstrate upgrade on independently V1-written stores before rollout. Failure must retain files and show actionable load error, never reset/fallback-empty/abandon old data. Old-app downgrade after V2 unsupported, must fail closed. Test failed/interrupted upgrade on disposable V1 fixtures; destructive framework behavior requires escalation, not an invented restore system or compatibility claim. Migration is not backup.

**Demonstrated transition detail:** SwiftData can finish the schema transition before a failing custom `didMigrate` marker save. On existing-root initialization only, recognize the exact same-mode V1 marker in an otherwise fully validated V2 graph with zero image assets/links; finish only that marker save under the root lock, preserving marker UUID and all revisions/content. Wrong mode/unknown marker/invalid graph still fail closed. A failed completion retains the old marker for retry; ordinary load/mutations never accept V1 markers. This narrow in-place completion is part of the approved compatibility intent, not generic restore or a power-loss guarantee.

## 4. Original Files and Ownership

**Proposed support/limits:** JPEG, PNG and ImageIO-supported single-primary-image HEIC/HEIF on iOS17.5; preserve received bytes, resolution, color profile, metadata and EXIF orientation without recompression/rotating originals. `.current` avoids requested conversion but does not prove a camera master: original means **exact received representation**, not RAW/unedited master. Reject animated/multi-frame files (except HEIF auxiliary representations), GIF/TIFF/RAW/PDF/video visibly, never convert silently. Live Photo still accepted only if provider supplies supported still; no motion. Verify actual type/decodability, not extension. HEIF auxiliary/edited/Live Photo behavior needs focused device evidence; if ambiguous, reject rather than flatten silently.

- **50 MiB (52,428,800 bytes) per original; 50 million pixels; 32,768 pixels per edge; 10 selections/batch; 20 saved images/owner.** Accommodates48MP stills and tall screenshots while bounding copy/decode/list work. No whole-notebook quota/dashboard/automatic deletion. Enforce streaming bytes and checked dimension arithmetic before decode. Show specific exceeded limit and Remove/reselect guidance; never shrink an original to pass. Low space can fail below limits. Revisit only with evidence/owner decision.
- Finish copying provider file within URL/access lifetime, including security-scoped access if supplied; do not persist provider URLs. Sequential chunked copy into `Application Support/<this TextNotebook root>/Images/Staging/<operationUUID>/`, incremental SHA-256, bounded work. App-generated path components only, regular-file/no-symlink/traversal checks; filenames only metadata. Ready requires closed, copied and validated file; no `UIImage` round-trip. Cloud-only selection may need network; saved reading must not.
- Immutable originals: same root's `Images/Originals/<assetUUID>.<validated extension>`, exclusive same-volume publication, never overwrite. Existing `completeUntilFirstUserAuthentication` protection. Directory/protection/close/flush checks precede metadata acknowledgment, not merely preview success. Atomically persist a small operation manifest of allocated keys/source marker and pending removals **before** final publication. This tracks orphan ownership, not durable user editing or archive recovery.
- Share an in-process per-root gate across windows for final revalidation/publication/metadata/reclamation, plus active-operation registry. Copy can happen outside gate; register owned keys first and invalidate late callbacks on cancel. Do not keep SwiftData context/transaction across provider awaits. Publish/verify all new regular originals (size/hash) first; then one metadata transaction inserts assets/links/order/captions and increments route/notebook revisions once. UI success follows save. Cache/manifest cleanup after commit cannot turn success into reported Save failure.
- Failure rolls back metadata; this operation's published files remain owned retry candidates, not saved rows. Reuse IDs/keys only with matching bytes; mismatches conflict. Narrow identical-batch retry may acknowledge a committed batch without another revision/insertion, never upsert later changes; fresh source/owner read decides. Restart displays committed graph, never automatically replays a manifest.
- Discard removes only operation-owned unreferenced files after workers drain. Removal/parent deletion commits detach, unused asset-metadata deletion and renumbering first; reclaim originals/caches only afterward under gate with fresh reference check. Preserve any surviving asset/link/active-operation reference even if sharing unexpectedly exists. Never delete files as compensation for failed metadata save.
- On root open, after successful migration/graph load and before image work, reconcile only known manifests against fresh committed keys. Committed keys survive commit-before-ack; inactive uncommitted operation files may be removed. Pending-removal manifests retry safe unlink. No age-deletion of originals, unrelated namespace sweep, malformed-key traversal, or reclamation when graph/ownership uncertain. Cleanup failure keeps manifest, retries next open, remains nonfatal to notes and reports retained-temporary-files/space guidance rather than claiming cleanup. All windows share active registry. No draft restoration claim.
- Orientation-correct bounded thumbnails are derived Caches data, keyed by source/asset/hash/recipe, regenerable if missing/corrupt. Never an original substitute. Reader reads original with memory-bounded downsampling/tiled display as needed, retaining native-pixel detail; list never eagerly decodes all50MP originals. If baseline-device memory cannot support budget/readability, reduce approved budget before rollout rather than promise blurry full-resolution reading.

**Isolation/privacy:** separate Notebook/Examples/test roots, retained/diagnostic roots untouched even with matching UUIDs. No network client, content logs/analytics, Photos write/delete APIs or persistent Photos-ID dependency. Exact copy retains potentially private location metadata; disclose locally, no silent stripping. User must have permission to retain third-party content; no real guidebook bundle, website bypass or redistribution. Synthetic samples are not navigation advice. App uninstall/device loss can lose files; system backup is not app backup/restore. Originals must not live in purgeable Caches/tmp or inherit export's exclude-from-backup temporary policy.
